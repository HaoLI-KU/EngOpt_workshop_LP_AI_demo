Linear Programming

How to make the best decision when everything is a straight line

1. What is linear programming?

Linear programming (LP) is a method for choosing the values of some decision variables so that a quantity you care about (profit, cost, weight, time) is as large or as small as possible, while respecting a set of limits.

The word linear means that the objective and every limit are sums of the variables times constants: no squares, no products of variables, no sin. The word programming is old-fashioned: it means "planning", not "writing code".

LP is everywhere: production planning, diets, transport and logistics, blending fuels, scheduling staff, airline crews, power grids. Very large LPs (millions of variables) are solved routinely.

2. The three ingredients

Decision variables

What you get to choose. Example: how many units of each product to make, x and y.

Objective function

What you want to maximise or minimise, written as a linear function, e.g. profit = 50x + 100y.

Constraints

The limits, as linear inequalities or equalities, e.g. 10x + 5y ≤ 2500, and usually x, y ≥ 0.

In general form, with n variables and m constraints:

minimise f(x) = c₁x₁ + c₂x₂ + … + cₙxₙ = cᵀx subject to Ax ≤ b x ≥ 0

Maximising profit is the same as minimising minus the profit, so one form covers both.

3. A worked example: the machine shop

A firm makes two machine parts, I and II, on three kinds of machine. Each part needs some minutes on each machine, and each machine has a limited number of minutes per week.

MachinePart I (min/unit)Part II (min/unit)Available (min/week)
Lathes1052500
Milling machines4102000
Grinding machines11.5450
Profit per unit$50$100

Let x = units of part I per week and y = units of part II per week. Then:

maximise P = 50x + 100y (weekly profit, $) subject to 10x + 5y ≤ 2500 (lathe minutes) 4x + 10y ≤ 2000 (milling minutes) x + 1.5y ≤ 450 (grinding minutes) x, y ≥ 0

Part II earns twice as much, so why not make only part II? Let's look.

4. See it: the graphical method

With two variables we can draw the problem. Each constraint is a straight line; the allowed side of all of them together is the shaded feasible region. Every point in it is a production plan the factory can actually run.

Drag the slider to push the profit line upward. Every point on the line earns the same profit. The best plan is the last point of the region the line touches before it leaves.

5. Why the answer is always at a corner

Because the objective is linear, its level lines are parallel straight lines, and the profit grows steadily in one direction. The feasible region is a convex polygon (in higher dimensions, a polytope). Sliding a straight line across a polygon, the last contact is always a corner (or, in a tie, a whole edge that includes corners).

So we only need to check the corners:

Corner (x, y)Which limits are tightProfit 50x + 100y
(0, 0)x = 0, y = 0$0
(250, 0)lathes, y = 0$12,500
(0, 200)milling, x = 0$20,000
(187.5, 125)lathes and milling$21,875

Making only part II, the best you can do is 200 units ($20,000): the milling machines run out. Mixing in some part I uses the lathes, which had spare time, and lifts profit to $21,875. Grinding is never a bottleneck: at the optimum 75 grinding minutes sit idle.

This is the fundamental theorem of LP: if an LP has an optimal solution, at least one optimal solution is at a vertex (a "basic feasible solution") of the feasible region.

6. Beyond two variables: the simplex method

Real problems have hundreds or millions of variables, so drawing is out. But the corner idea survives. A polytope can have a huge number of corners, so checking them all is hopeless; the simplex method (George Dantzig, 1947) walks from corner to corner instead, always uphill:

  1. Standard form. Turn each ≤ into an equation by adding a slack variable: 10x + 5y + s₁ = 2500, with s₁ ≥ 0 the unused lathe minutes.
  2. Start at a corner. Here, x = y = 0 with all slacks equal to the full capacities (make nothing, use nothing).
  3. Pick a direction that improves the objective. If no neighbouring edge improves it, the current corner is optimal: stop.
  4. Move along that edge until a constraint blocks you (the ratio test). That is the next corner. This swap is a pivot.
  5. Repeat from step 3.

For the machine shop, simplex goes (0, 0) → (0, 200) → (187.5, 125): two pivots. In practice simplex usually needs a number of pivots of the order of the number of constraints. Interior-point methods are the main alternative: they cut through the inside of the region instead of walking its edges.

7. A bonus answer: shadow prices

Solving an LP tells you more than the best plan. Each constraint gets a shadow price (or dual value): how much the optimal objective would improve if that limit were relaxed by one unit.

ResourceUsed at optimumAvailableSlackShadow price
Lathes250025000$1.25 / min
Milling200020000$9.375 / min
Grinding37545075$0 / min

Reading: an extra minute of milling is worth about $9.38 of profit, an extra lathe minute only $1.25, and extra grinding time is worth nothing because some is already idle. If you can buy capacity, buy milling first. A constraint with slack always has a zero shadow price (complementary slackness).

Check: 2500 × 1.25 + 2000 × 9.375 = $21,875, exactly the optimal profit. That is no coincidence: it is LP duality.

8. Solving it in MATLAB

MATLAB's linprog (Optimization Toolbox) minimises f'*x subject to A*x ≤ b, so we minimise minus the profit: 

% minimise -50x - 100y  (= -profit)
f  = [-50; -100];
A  = [10  5;  4 10;  1 1.5];
b  = [2500; 2000; 450];
lb = [0; 0];

[x, fval, exitflag, ~, lambda] = linprog(f, A, b, [], [], lb);

x                   % [187.5; 125]
profit = -fval      % 21875
lambda.ineqlin      % shadow prices [1.25; 9.375; 0]

The repository's course_material/l02_demo_ex32.m does exactly this, checks the answer against the hand-computed simplex tableau, and draws the feasible region.

9. What can go wrong, and what LP cannot do

Infeasible

The constraints contradict each other, so the feasible region is empty. No plan exists.

Unbounded

The region is open in a direction that keeps improving the objective, so there is no best value. Usually a missing constraint.

Many optima

The profit line is parallel to an edge of the region: every point on that edge is optimal.

And some problems are not LPs at all:

  • Whole numbers. The optimum says 187.5 parts; you cannot make half a part. Requiring integers gives integer programming, which is much harder. Rounding is not always safe: it may break a constraint or miss the true best.
  • Curves. If profit per unit falls as you sell more, or a constraint involves x², the problem is nonlinear and the corner argument no longer holds.

Summary

  • An LP has decision variables, a linear objective and linear constraints.
  • The constraints carve out a convex feasible region; the optimum sits at a corner.
  • Simplex walks from corner to corner, uphill, until no neighbour is better.
  • Shadow prices tell you which limit is worth relaxing, and by how much.
  • Check the answer: is it feasible, does it make physical sense, and are integers needed?
