Linear programming, explained with the workshop

Engineering Optimisation, Lecture 2 · Rao's Example 3.2 (5th ed., Section 3.4)

1The problem

A firm makes two machine parts. Each part needs time on three machine groups: lathes, milling machines and grinders. Each group has a fixed number of minutes per week. How many of each part should the firm make to earn the most profit?

MachinePart I (x)Part II (y)Available / week
Lathes10 min5 min2500 min
Milling4 min10 min2000 min
Grinding1 min1.5 min450 min
Profit / unit$50$100

Down a column: one part's recipe. Across a row: one machine group's weekly budget.

2Writing it as a linear program

Three ingredients turn the story into mathematics:

  1. Design variables: x and y, the number of Part I and Part II made per week.
  2. Objective: profit P = 50x + 100y should be large. We always minimise, so we minimise f = −P.
  3. Constraints: no machine group may use more minutes than it has, and production cannot be negative.
minimisef = −50x − 100y(−profit, $/week) subject to10x + 5y ≤ 2500lathes 4x + 10y ≤ 2000milling x + 1.5y ≤ 450grinding x, y ≥ 0
It is linear because the objective and every constraint are sums of constants times variables: no products like xy, no powers, no square roots. That one property is what makes the rest of this page work.

3Solving it by drawing

With two variables we can draw the problem. Each constraint, written with “=”, is a straight line; the “≤” keeps the side towards the origin. The feasible region is where all constraints hold at once (shaded). The dotted lines are contours of equal profit, 50x + 100y = k. Slide the contour outwards: the last point of the region it touches is the optimum.

lathes milling grinding profit contour
Straight contours ⇒ the answer is at a corner. A linear objective keeps increasing in one direction, so it can only stop where the region stops: at a vertex (or, in a tie, along a whole edge).

So we only need to check the corners:

  • Two constraints active, one not. Lathes and milling are fully used. Grinding uses 187.5 + 1.5·125 = 375 of 450 minutes: 75 minutes idle.
  • The optimum is not a whole number. You cannot make 187.5 parts. That is honest, not an error; fixing it needs integer programming.

4Solving it with the simplex method

Drawing stops working at three variables. The simplex method does the same corner search algebraically:

  1. Add a slack variable to each ≤ constraint to make it an equation, e.g. 10x + 5y + s1 = 2500. The slack is the unused minutes.
  2. Start at a corner (the origin: make nothing, all slack).
  3. Pivot to a neighbouring corner whenever that lowers f. Stop when no neighbour is better.

For the workshop, two pivots reach the optimum. The final tableau:

How to read it:

  • Optimal? Yes: no negative entry in the −f row, so no neighbouring corner is better, and for a linear (convex) problem that means none anywhere is.
  • The plan: x and y are basic, so read their RHS: x* = 187.5, y* = 125. Profit $21 875 per week.
  • Bottlenecks: s1 and s2 are zero (non-basic), so lathes and milling are fully used. s3 = 75: grinding has 75 idle minutes.

5Shadow prices: what is one more minute worth?

Shadow price of a constraint: how much the optimal objective improves per unit relaxation of that constraint's limit.

They come for free: they are the slack columns of the −f row.

ResourceUsedAvailableSlackShadow price
Lathes250025000$1.25 / min
Milling200020000$9.375 / min
Grinding37545075$0 / min
  • Milling is the real bottleneck. One more milling minute earns $9.375; if you buy capacity, buy this first.
  • An idle resource is worth nothing. 75 grinding minutes are unused, so a 451st is worth $0.
  • Active does not mean valuable. Lathes are also fully used, but worth far less than milling.

Try it in the graph above: move the milling slider from 2000 to 2001 and watch the profit rise by $9.375.

6Solving it in MATLAB

linprog minimises f = cTx subject to Ax ≤ b and bounds. The problem is already a minimisation, so the vector is c itself.

f = [-50; -100];               % f = -50x - 100y, exactly as formulated
A = [10 5; 4 10; 1 1.5];       % lathes; milling; grinding
b = [2500; 2000; 450];
opts = optimoptions('linprog','Display','none');
[x, fval, ~, ~, lambda] = linprog(f, A, b, [], [], [0;0], [], opts);
x, -fval, b - A*x, lambda.ineqlin

What it prints (MATLAB R2025b):

x              = 187.5   125
-fval          = 21875
b - A*x        = 0       0      75
lambda.ineqlin = 1.25    9.375  0

Identical to the hand tableau. The full script, course_material/l02_demo_ex32.m, checks the two against each other to 10−6 and redraws the graph.

7A warning: change one number

Drop Part I's profit from $50 to $40. Now the profit contours are parallel to the milling line (40 : 100 = 4 : 10), so every plan on the edge from (0, 200) to (187.5, 125) earns the same $20 000.

AlgorithmxyProfit
dual-simplex0.00200.00$20 000
interior-point140.96143.62$20 000
  • Simplex only visits corners, so it lands on an end of the edge. Interior-point comes from inside and stops along it.
  • Both are correct, but they are different designs: one part (one setup) versus both parts.
  • Look at the answer, not only the objective value.

Try it: set the Part I profit slider to $40 and the whole milling edge lights up.
